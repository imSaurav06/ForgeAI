2. P0-2: TEST EXECUTION MUST NEVER FALSE-PASS
- File: services/agent/app/core/workflows/orchestrator.py (_execute_pytest)
- Forensic Defect Identified:
  * Line 521 previously contained `passed = data.get("exit_code") == 0 or data.get("exit_code") == 5 or data.get("status") == "success"`.
  * Exit code 5 (no tests collected) was treated as passing.
  * Generic `status: success` from HTTP wrapper could override non-zero test exit codes.
- Remediation Applied:
  * Strict fail-closed contract: `passed = bool(data.get("exit_code") == 0 and data.get("passed") is True)`.
  * Any non-zero exit code (including 1 for failure, 5 for no tests) strictly evaluates to `passed=False`.
  * Non-200 HTTP responses, tool errors, timeouts, and network exceptions strictly return `passed=False`.

- Forensic Defect Identified:
  * Need machine-verifiable guarantee that tests execute strictly within the designated repository_id.
  * If repository_id is missing or invalid, operation must not fall back to an arbitrary workspace.
- Remediation Applied:
